# Architect: evolved Copilot form

Latest user direction: the previous family sheet looks like a reskinned Copilot. The new Architect needs actual features and form changes, as if Copilot evolved. This combines two constraints: preserve recognizable Copilot ancestry, and remodel primary anatomy rather than only adding accessories.

Retain the compact broad head character, convex dark display, two capsule eyes and recognizable side modules. Change the crown volume, cheek/jaw structure and side housing silhouette in each concept. Express Application Architect through physical layers, bounded modules, linked interfaces and structural continuity. Avoid unrelated robot/body designs, civil construction imagery, oversized drafting tools, floating diagrams and unchanged base geometry with icon badges.

Six directions:

01 Boundary Builder — Defines domains with a structured shell.
02 Layer Architect — Application layers shape the entire silhouette.
03 Interface Weaver — Connects interfaces through paired crown structures.
04 Module Architect — Interlocking modules form one coherent application.
05 Systems Planner — A broad planning crown organizes components.
06 Contract Architect — Shared contracts unite structured service modules.

Illustrative concept designs; no measured topology or production geometry claimed. No option selected yet. Earlier two sheets are rejected exploration and cannot establish accepted production direction. Existing source/runtime remain preserved during review.
