# Application verification

The suite includes core/content/integration/build checks, desktop/touch browser cases, and landscape/subdirectory deployment checks. The [mechanics guide](../../docs/Test_Map_Mechanics.md) records coverage configuration, authored path clearance, drag aiming, wave recipes, repeatable attempts and custom saves. [Tower and Copilot core properties and stats](../../docs/Tower_Base_Stats.md) describes authored cost/footprint, performance overrides, Copilot extension boundaries and validation. Existing lab browser cases now enter `#/lab`; old pure probe tests remain regression fixtures. Preset isolation, stale tabs, legacy preservation, map clicks, inspection, gesture cancellation and pause locks are covered. Four browser workers avoid excessive contention with the strict frame-gap pause policy.

Run `npm test` for core/content/integration/build checks and `npm run build` followed by `npm run test:e2e` for browser checks. `npm run test:deployment` builds and serves the app under `/TowerDefense/` on port 5184. `npm run verify` runs the complete sequence including lint, import boundaries and both browser configurations. Vitest uses its own configuration; delivery tests explicitly instantiate the asset plugin in isolated fixture builds and dev servers.

`build/runtimeAssets.test.ts` covers versioned selection, invalid delivery, source-metadata exclusion, zero-model builds, three deployment bases, development serving, and the repository's registered Copilot export. It never edits production assets.

`integration/homeBoot.test.ts` covers startup ownership, progress, timeout, retry, cancellation, stale results, runtime failure, routing and preference storage. Campus tests check versioned composition, complete loading and bounded/cancellable asset loading. `e2e/home.spec.ts` exercises the actual built home, camera, lazy lab, settings, denied storage, reduced motion, failed GLB retry, WebGL fallback, context-loss recovery and navigation on desktop and touch emulation. `deployment/startup.spec.ts` covers subpath URLs, landscape layout, failed initial JavaScript and failed renderer-chunk recovery. Browser screenshots live under `test-results/`; `test:deployment` uses its own output directory and generated build there.

Current coverage: malformed content, duplicate/dangling references, logical geometry boundaries, command rejection, fixed timing, complete-once events, detached snapshots, restore continuation, save eligibility, stale repository revisions, cached UI snapshots, session disposal, hidden-tab freeze, and late async results. Browser tests exercise start/pause/resume, real IndexedDB across reloads and tabs, pointer/touch placement, and narrow layouts. Evidence screenshots are generated beneath ignored `test-results/`.

`fixtures/helpers.ts` supplies deterministic scenarios and a controllable frame host. The [wider verification plan](../../docs/Codebase_Structure.md#verification-plan) covers later gameplay and performance work; those cases are not implemented yet. Existing asset-tool verification stays under its respective tool.

`integration/campusLifecycle.test.ts` verifies the actual Copilot v02/Developer clip contracts, sparse scheduling, stationary playback, reset, disposal and template isolation. With the Vite dev server running, `/tests/fixtures/campusLifecycleReview.html` reviews both actual GLBs and an unaffected Copilot clone using the production lifecycle presenter, including midpoint cubes, absence, reassembly and reduced-motion reset.


`integration/showcaseLoading.test.ts` covers bounded fetch/decode, cancellation and late model disposal. `e2e/mobileQuality.spec.ts` uses real browser multi-touch dispatch for campus pan/pinch and preview orbit/pinch, checks 44px targets across rotation, verifies scene diagnostics cleanup, and exercises failed JavaScript and stalled model recovery. Captures and renderer samples are stored in each test output folder. Append `?diagnostics` when manually sampling render counts; the registry is absent by default. CI uses Playwright Chromium, while local Windows checks use Edge.

The Pages workflow now runs `npm run verify` before `npm run build:pages` and uploads `game/dist`. `build-info.json` includes the CI source revision and SHA-256 file manifest. Publishing remains a separate remote workflow action.
