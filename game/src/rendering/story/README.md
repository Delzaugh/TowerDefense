# Standalone story experiment

Launch **Play story scene · 42 sec** from Home. The real-time scene uses Base Copilot v02, Classic Low Poly Octocat v01 and two instances of Bug v01. A coffee promise becomes an ambush: the audience spots the Bugs first, Copilot notices, Octocat turns, a carrier slides in and locks, Octocat resists, and the Bugs haul the captive away. Copilot keeps the promise in the closing close-up. This is proposed story content, not a campaign commitment.

`../../content/story/octocatAbduction.ts` owns dialogue windows, ten camera shots, actor blocking, performance cues, capture beats and the duration. It is pure data/functions: arbitrary backwards seeking and replay produce the same staging. The presentation samples both sides of a 220ms blend by absolute time; one-shot actions hold their last pose.

`assets.ts` pins catalog-registered model versions to roles. Twelve additional `story_*` clips live in the authoritative character sources alongside unchanged gameplay clips. `createStoryScene.ts` clones the skeletons and selects authored clips; wrapper groups own position/facing. The renderer does not edit bones or character materials. The new `story_courtyard` and `story_capture_carrier` GLBs have their own Blender sources and manifests. `effects.ts` owns the brief anchored exclamation, deployment pulse, lock sparks and tow connections. Future character appearance assembly should enter at `createActor`: supply the same customised instance used by gameplay, preserving its rig, clips and attachment anchors. The current application has no character-customisation system to read yet.

Bug cinematic locomotion uses baked two-link leg solving in Blender, with measured nominal travel per cycle: `story_creep` = .65m / 44 frames at 24fps; `story_haul` = .70m / 32 frames. The timeline derives clip phase from accumulated staging distance, rather than letting feet loop at a speed unrelated to travel. Changes to these clips' stride or duration must update the timeline values together. Shared gameplay `move` remains intact.

`../../app/story/StorySceneDialog.tsx` owns the isolated canvas, lazy renderer import, load/retry, transport, subtitles and focus. Optional Web Audio synthesis in `storyAudio.ts` starts only from the sound button and has no media downloads. Close, retry, navigation, hidden-tab suspension and reduced motion stop the appropriate resources. Reduced motion presents still shots with manual navigation and dialogue; no automatic camera movement runs.

The Home integration has one launch action and pauses campus rendering while the modal is open. Nothing imports story content from simulation, progression, saves, session or gameplay definitions. To remove the experiment, remove `StorySceneDialog` and its `storyOpen` launch/pause wiring from HomeScreen, remove the story button/props from HomeView/homeTypes and the `.home-story-button` style, then remove the story app/rendering/content directories and their focused tests. No migration or save changes are needed.

The independent renderer targets 30 FPS, caps DPR at 1.5 on narrow viewports / 2 elsewhere, uses one 1024-pixel shadow light and no post-processing passes. It fetches only five registered assets, with three concurrent loads, when opened. Read-only diagnostics are available with `?diagnostics` under `window.__TOWER_DIAGNOSTICS__.story`, including selected clips, expression and trap phase; no mutation/debug hook is shipped.

Validation: `npm run typecheck`, `npm run lint`, `npm run check:boundaries`, `npx vitest run tests/content/storyTimeline.test.ts`, then an isolated build and focused Playwright run. Browser tests cover desktop/touch playback and interruption, expression/capture timing, real exported clips, seeks/replay, missing-asset recovery, focus, cleanup and reduced-motion layout. The original technical-demo evidence remains under `artifacts/story-scene-20260930/`; the polish pass has its own recordings and review under `artifacts/story-polish-20260930/`.
